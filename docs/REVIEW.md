# بازبینی محتوا توسط متخصص HSE

همه‌ی محتوای فعلی (۸۵ سؤال، ۳۲ سناریوی ریسک، ۱۰ خطر در یک صحنه، ۱۴ مجوز کار، ۱۵ موقعیت اضطراری و ۱۲ پاپیون) `draft` است: نوشته شده ولی هنوز هیچ متخصصی صحتش را تأیید نکرده است. برنامه آموزشی است و اگر محتوایش غلط باشد می‌تواند عادت اشتباه بسازد؛ پس **انتشار بدون این بازبینی مجاز نیست** (`npm run verify:release` تا زمانی که چیزی `draft` است رد می‌کند).

## جریان کار

```bash
npm run content:export                  # برگه‌ها را در review-sheets/ می‌سازد
# → برگه‌ها (quiz-review.csv، risk-review.csv، hazard-review.csv، permit-review.csv، emergency-review.csv، bowtie-review.csv) را برای بازبین بفرستید
npm run content:apply -- review-sheets/quiz-review.csv --reviewer "نام بازبین" --date 2026-10-03
npm run content:apply -- ... --write    # فقط وقتی خروجی بالا درست بود
npm run check
```

`content:apply` بدون `--write` فقط می‌گوید چه می‌کرد. با `--write` هر ردیف «تأیید»شده `reviewed` می‌شود و **نام و تاریخ بازبین** کنار آیتم در بسته‌ی محتوا (`review`) ذخیره می‌شود. چیزی که برگردانده شد (`changes`/`reject`) به `draft` برمی‌گردد (و اگر پیش‌تر `reviewed` بود، تأییدش لغو می‌شود). این ابزار هرگز خودش چیزی را «درست» تشخیص نمی‌دهد؛ فقط تصمیم یک آدم را ثبت می‌کند.

## چه چیزی برای بازبین فرستاده شود

هر برگه یک جدول CSV است (در Excel یا Google Sheets باز می‌شود، فارسی درست نمایش داده می‌شود). به بازبین بگویید برای هر ردیف این‌ها را بسنجد:

۱. **صحت فنی:** پاسخ درست، درست است؟ گزینه‌های غلط واقعاً غلط‌اند و ابهام ندارند؟
۲. **استاندارد و مقررات:** توضیح با استاندارد/قانونِ جاری می‌خواند؟ مرجع (استاندارد و بند) درست است؟ در جاهایی که به ایران مربوط است (شماره‌های اضطراری ۱۱۵/۱۲۵/۱۱۰، مقررات وزارت کار، آیین‌نامه‌های ایمنی) قانون درست نقل شده؟
۳. **«نظر کارشناس» در سناریوها و خطرها:** رتبه‌ی احتمال و شدت و جایگاه هر کنترل در سلسله‌مراتب کنترل (حذف > جایگزینی > مهندسی > اداری > PPE) معقول است؟ این‌ها استاندارد نیستند، قضاوت حرفه‌ای‌اند و جواب درست یکتا ندارند.
۴. **زبان:** اصطلاح فارسی رایج در صنعت است؟ مبهم یا ترجمه‌ی تحت‌اللفظی نیست؟
۵. **سختی:** درجه‌ی ۱ تا ۳ مناسب است؟

### ستون‌های برگه

| ستون | کار |
|---|---|
| `game`، `id`، `topic`، `difficulty`، `item`، `content`، `explanation`، `references`، `status` | **فقط خواندنی.** خودِ آیتم. `content` متن سؤال/سناریو/خطر با پاسخ درست (✔) است |
| `add_references` | **اختیاری، پر کردن با بازبین.** مرجعی که باید اضافه شود، هر مرجع در یک خط: `ISO 45001:2018 §8.1.2` (بند بعد از علامت § و توضیح اختیاری در پرانتز بعد از بند: `ISO 45001:2018 §8.1.2 (سلسله‌مراتب کنترل)`). بدون § کل خط نام استاندارد حساب می‌شود (`ILO C155 (1981)`) |
| `verdict` | **حتماً پر شود.** یکی از `approved` (تأیید)، `changes` (نیاز به اصلاح)، `reject` (رد). خالی = هنوز بررسی نشده و دست نمی‌خورد. فارسی هم پذیرفته می‌شود: «تأیید»، «اصلاح»، «رد» |
| `notes` | توضیح بازبین؛ برای `changes` و `reject` بنویسید چه باید عوض شود. در خروجی `apply` چاپ می‌شود تا نویسنده اصلاح کند |

**برگه‌ی خطر (`hazard-review.csv`):** هر ردیف یک خطر است، ولی بازبینی روی کل صحنه ثبت می‌شود: صحنه فقط وقتی `reviewed` می‌شود که **همه‌ی** خطرهای آن `approved` باشند. بازبین باید تصویر صحنه را هم کنار برگه ببیند (محل دایره‌ی خطر در ستون `content` به درصد آمده است). تا وقتی تصویر `site-01` موقت است، بازبینی این برگه معنای نهایی ندارد.

## چیزی که اکنون می‌دانیم

- **مرجع ندارند:** ۶۹ از ۸۵ سؤال و هر ۱۰ خطر `references` خالی دارند. `apply` عمداً `approved` را برای آیتمِ بدون مرجع نمی‌پذیرد (قاعده‌ی schema هم همین است). مرجع نمی‌تواند حدسی باشد: بازبین باید در `add_references` بنویسد، و ابزار فقط ثبتش می‌کند. مرجع‌های موجود فقط ISO 45001 (۴۱ مورد)، ISO 14001 (۴) و ILO C155 (۳) هستند.
- **موارد حساس‌تر برای دقت:** شماره‌های اضطراری ایران، توصیه‌های کمک‌های اولیه/برق‌گرفتگی، هر عدد در توضیح‌ها، و رتبه‌ی احتمال/شدت سناریوها و خطرها.
- **حجم:** هدف v1 حدود ۳۰۰ سؤال، ۴۰ سناریو و ۸ صحنه است. پیشنهاد این است که **اول دور اول بازبینی انجام شود** (۸۵ + ۳۲ + صحنه‌ی موجود) تا سلیقه‌ی بازبین مشخص شود و بقیه‌ی محتوا به همان سبک نوشته شود، نه این‌که صدها سؤال draft دیگر روی میز بازبین بریزیم.

## بعد از بازبینی

`npm run verify:release` باید پاس شود. `reviewStatus` را فقط این جریان عوض می‌کند؛ دستی `reviewed` نوشتن، schema را رد می‌کند (نبودن `review`) و تست‌ها می‌شکنند.
